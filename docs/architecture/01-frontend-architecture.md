# 前台架构：共创客户端与实时仲裁室

前台是用户参与 AI 协作的控制台。它负责交互和审核，不负责模型推理，也不直接写入知识库。

---

## 1. 定位

前台承载四类能力：

1. **任务入口**：收集任务目标、业务材料、补充说明和用户约束。
2. **沙盒直播**：实时展示 PM、Tech、QA、Reviewer 的讨论、审查和状态变化。
3. **人类仲裁**：允许用户打断错误方向、裁决死锁争议、确认关键取舍。
4. **法则审核**：展示 Diff Agent 提炼出的候选法则，由用户决定是否入库。

## 2. 页面模块

| 模块 | 职责 |
|---|---|
| 任务启动区 | 创建任务，提交目标、材料和约束 |
| 群聊直播区 | 展示子 Agent 的实时发言、轮次、分歧和收敛状态 |
| 仲裁面板 | 展示待用户拍板的争议点、各方立场和风险说明 |
| 共创编辑器 | 展示草稿，支持用户修改并保存终稿。包含阅读模式（Markdown 渲染）与编辑模式（源码输入），支持通过 Header Actions 的单 Icon 双态控制按钮（Pencil / BookOpen）自由无缝切换，且支持在阅读模式下直接点击正文一键跳转编辑。 |
| 知识管理页 | 上传知识材料，查看导入状态和索引结果 |
| 法则审核页 | 审核候选法则，支持直接批准入库、修改后入库（支持在模态框中修改法则标题及描述后入库）、限定作用域与驳回 |

## 3. 交互链路

```text
创建任务
  -> 订阅任务事件流
  -> 查看子 Agent 讨论
  -> 必要时打断或仲裁
  -> 查看 Reviewer 门禁结果
  -> 编辑并保存终稿
  -> 审核候选法则
```

## 4. 打断机制

用户发现方向错误时，可以发出打断指令。中台收到后需要：

1. 停止当前推演轮次。
2. 保存打断原因和用户指令。
3. 将用户指令作为下一轮高优先级约束。
4. 在前台显示任务已转向。

## 5. 仲裁机制

当 PM、Tech、QA 在限定轮次内无法收敛时，前台展示：

- 争议主题。
- PM、Tech、QA 的核心立场。
- 每个选项的收益、代价和风险。
- 推荐裁决项及理由。

用户裁决后，后续推演必须服从该裁决。

## 6. 终稿与法则审核

终稿保存只代表交付内容冻结，不代表知识自动入库。候选法则必须经过人工审核：

```text
用户保存终稿
  -> 系统冻结草稿、终稿、版本差异和仲裁记录
  -> Diff Agent 提炼候选法则
  -> 前台展示候选法则
  -> 用户审核并设置作用域
  -> 可信法则写入 GBrain
```

## 7. 前台约束

- 前台不保存模型密钥。
- 前台不直接调用模型推理。
- 前台不直接写入 GBrain。
- 所有打断、仲裁、保存和审核动作都要可追溯。
- 降级状态、未收敛争议、审核失败和知识过期必须显式提示。
